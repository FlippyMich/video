# Deliverables

Everything here is produced by `pipeline/run-all.sh` from
`content/buzzys-senseational-adventure.script.txt`. Nothing is hand-made, and
re-running the pipeline reproduces all of it.

---

## video/

| File | What it is |
|---|---|
| `buzzys-senseational-adventure-1080p.mp4` | **The master.** 1920×1080, 16:9, 30fps, H.264 + AAC. Captions are *not* burned in — upload the `.srt` alongside it so viewers can turn them on and YouTube can translate them. |
| `buzzys-senseational-adventure-1080p-captions.mp4` | The same film with captions burned into the picture. For places that cannot carry a subtitle track. |
| `buzzys-senseational-adventure-1080p-greenscreen.mp4` | Characters and animation on flat chroma green (`#00B140`), with flat shadowless lighting. Same cut, same sound. |
| `buzzys-senseational-adventure-1080p-upload.mp4` | The same film at a lower bitrate. Visually the same after YouTube's own re-encode, and small enough to send to somebody or keep in the repository. |
| `buzzys-senseational-adventure-thumbnail.jpg` | A poster frame. |

> **The video files here are one revision behind the code.** They were rendered
> before the fix that stopped the winged characters strobing (their wings were
> keyed at a real insect wingbeat, which at 30fps read as vibration). The
> pipeline carries the fix; re-running stage 3 replaces these files. That
> re-render is being held until the real voice recordings arrive, because the
> cut is built from the voice timings and would have to be rendered twice
> otherwise.

Only the upload cut and the thumbnail are committed. The masters are 340–360 MB
each, past GitHub's 100 MB limit per file; `node pipeline/03-render.mjs`
reproduces them.

**Uploading to YouTube:** use the master, add the `.srt` from `captions/` as an
English subtitle track, and set the thumbnail. The file is already
`faststart`-muxed and at a bitrate above YouTube's re-encode threshold.

## audio/

| File | What it is |
|---|---|
| `full-mix.wav` / `.m4a` | The finished mix, as heard in the video. 48kHz, 24-bit, normalised to about −15 LUFS. |
| `voiceover.wav` / `.m4a` | Dialogue only, in place on the timeline. |
| `music.wav` / `.m4a` | Music only, in place. |
| `sfx.wav` / `.m4a` | Sound effects only, in place. |
| `vo/` | Every line as its own file, in script order. |
| `music/`, `sfx/` | Every source cue, before placement. |
| `voice-timings.json` | Per-line durations and phoneme timings — this is what drives the cut and the lip-sync. |
| `audio-manifest.json` | Every generated cue and its length. |

The stems are the same length as the film and start at the same point, so they
can be dropped straight onto a timeline without alignment.

**A note on the voices.** They are synthesised (espeak-ng) — clear and precisely
timed, but a scratch track, not a performance. See
`docs/knowledge-base/replacing-the-voice-track.md` for how to swap in real
recordings; the pipeline retimes the film around them automatically.

The music and sound effects are **not** placeholders. They are generated by the
synthesiser in `pipeline/lib/synth.py` and carry no third-party rights.

## captions/

| File | What it is |
|---|---|
| `.en.srt` | For YouTube, Vimeo and anything that takes a sidecar subtitle file. |
| `.en.vtt` | The same cues for web players (`<track kind="subtitles">`). |
| `.en.ass` | The styled version used to burn the captions into the picture. It declares its own 1920×1080 script resolution, so the burned-in text matches what the studio draws rather than being scaled against a converter's default. |

English, 101 cues. Two lines maximum, about forty characters per line, split at
sentence boundaries and clamped so no two cues overlap.

## blender/

One `.glb` per scene, with baked animation and a camera that follows the film's
cuts, plus `import_project.py`.

```bash
blender --python deliverables/blender/import_project.py
```

Each scene arrives as its own collection, positioned on the timeline where it
sits in the film, with the render settings already matching the master.

**What is not in these files, and why:**

- **Particle effects** (sparkles, petals, confetti) are simulated per frame in
  the studio and have no glTF equivalent. The cue sheet lists where each one
  plays; recreate them with Blender's particle system.
- **Captions and audience overlays** are composited in 2D over the render. Add
  them in the sequencer, or use the `.srt`.
- **Audio** is delivered separately — load the stems into the sequencer.
- **Outlines.** The studio's toon outlines are inverted hulls; they are stripped
  on export because in any other renderer they appear as a dark shell around the
  model.

Materials arrive as standard PBR with the correct base colours. For the flat
look, switch them to Emission or reduce roughness.

## documents/

| File | What it is |
|---|---|
| `buzzys-senseational-adventure-final-script.docx` | The **as-broadcast script**: every line, cue and audience beat with the timecode it actually falls on, plus a production summary and notes for teachers. |
| `shot-list.csv` | All 120 shots — start, length, scene, framing, camera move, transition. |
| `cue-sheet.csv` | Every audio clip and audience beat in time order. |

The script document is generated from the finished film, not from the writer's
draft, so its timecodes match the delivered file frame for frame.
